# راهنمای اجرای نسخه‌ی self-hosted

> **این مسیر برای staging است و هنوز production-ready نیست.** کد فعال Next.js دیگر به Supabase متصل نمی‌شود: routeهای API از PostgreSQL، فایل‌ها از Storage محلی، و پرداخت/پیامک از providerهای بیرونی استفاده می‌کنند. Compose، DDL، restore و callback واقعی هنوز در VPS آزموده نشده‌اند. راهنمای اجرا و blockerها در [`self-hosted/README.md`](self-hosted/README.md) و [`../docs/deployment-readiness.md`](../docs/deployment-readiness.md) هستند.

## ۱) قبل از اجرا

- PostgreSQL 17، role محدود برنامه، migration runner، health readiness و volumeهای پایدار در Compose تعریف شده‌اند.
- دیتابیس می‌تواند تازه و خالی باشد؛ انتقال داده‌ی قدیمی الزامی نیست. `0001_initial_schema.sql` schema پایه را می‌سازد و پس از آن مدیر اولیه را با script تعاملی بسازید.
- اگر محیط production فعلی Supabase دارد، آن را خاموش یا تغییر ندهید؛ تا backup/rollback و پایان دوره‌ی پایش برای نسخه‌ی قبلی روشن بماند.
- هیچ SQL مقصد را روی پروژه‌ی Supabase اجرا نکنید؛ migrationهای جدید برای PostgreSQL self-hosted هستند.

## ۲) Environment

از ریشه‌ی repository:

```bash
./deploy/self-hosted/create-env.sh
```

اسکریپت رمزهای PostgreSQL و signing secret را تولید و `.env` را با permission محدود ایجاد می‌کند. فقط تنظیم‌های بیرونی لازم را به آن اضافه کنید:

### زرین‌پال

- `ZARINPAL_MERCHANT_ID`
- `ZARINPAL_SANDBOX=true` در staging
- `ZARINPAL_CALLBACK_URL=https://<دامنه‌ی فعلی>/payment-result`
- `PRICE_TO_RIAL_FACTOR=10` اگر قیمت دیتابیس تومان است یا `1` اگر ریال است

### پیامک OTP

در production یکی از providerها لازم است:

- sms.ir: `SMS_IR_API_KEY` و `SMS_IR_TEMPLATE_ID` یا line تنظیم‌شده برای Bulk
- کاوه‌نگار: `KAVENEGAR_API_KEY`
- `OTP_DEBUG=false` بماند.

Runtime به `SUPABASE_URL`، `SUPABASE_ANON_KEY` یا `SUPABASE_SERVICE_ROLE_KEY` نیاز ندارد. مقدارهای محرمانه را در Git، چت، image عمومی یا log قرار ندهید.

## ۳) اجرا و آزمون

```bash
docker compose --env-file .env -f deploy/self-hosted/compose.yaml config --quiet
docker compose --env-file .env -f deploy/self-hosted/compose.yaml build
docker compose --env-file .env -f deploy/self-hosted/compose.yaml up -d
```

سپس bootstrap مدیر و smoke testهای README self-hosted را اجرا کنید. پیش از cutover لازم است staging واقعی این موارد را بگذراند: migration از صفر، ساخت مدیر و دوره، ثبت‌نام/OTP، سبد/نشانی، پرداخت sandbox و callback، دانلود خصوصی، پنل مدیریت، backup خارج VPS و restore drill.

در وضعیت فعلی:

- ترتیب ثبت‌نام `otp-verify` و سپس `register-user` است؛ آن را تغییر ندهید.
- `/api/functions/[name]` یک bridge fail-closed با allowlist خالی است؛ همه‌ی APIهای فعال routeهای اختصاصی دارند.
- Edge Functionهای قدیمی فقط برای مرجع/rollback کد باقی مانده‌اند و برای اجرای نسخه‌ی self-hosted لازم نیستند.
- Supabase قبلی را فقط پس از backup/restore تأییدشده، rollback window و پایش خاموش کنید.
