# راهنمای سه قابلیت جدید: لودینگ، ویرایش محتوا از پنل، لوگوهای شبکه‌های اجتماعی

تاریخ: ۲ مهر ۱۴۰۵ (۲۴ سپتامبر ۲۰۲۶)

## ۱) انیمیشن لودینگ

### چه چیزی اضافه شد

| بخش | توضیح |
|---|---|
| **لودر تمام‌صفحه** | نشان آکادمی (نشان «ریاضی» با گرادیان بنفش) با انیمیشن نفس‌کشیدن + حلقه‌ی چرخان + متن «در حال بارگذاری…» + نوار نازک پیشرفت در بالای صفحه |
| **اسکلتون کارت دوره‌ها** | به‌جای متن «در حال دریافت لیست دوره‌ها…»، سه کارت خاکستری با درخشش متحرک نمایش داده می‌شود تا وقتی داده از API هم‌مبدأ و PostgreSQL برسد |
| **اسپینر دکمه‌ها** | تابع `btnLoading(دکمه, true)` روی هر دکمه‌ای اسپینر می‌گذارد (برای دکمه‌های پرداخت/ذخیره) |
| **احترام به تنظیم کاربر** | اگر کاربر در سیستم «کاهش انیمیشن» را روشن کرده باشد، همه‌ی انیمیشن‌ها خاموش می‌شوند |
| **بدون JS** | اگر مرورگر جاوااسکریپت را اجرا نکند، لودر با `<noscript>` پنهان می‌شود (صفحه گیر نمی‌کند) |

### فایل‌ها

- `css/loader.css` — ظاهر لودر و اسکلتون‌ها
- `js/loader.js` — کنار زدن لودر + ابزار `Skeleton` و `btnLoading`
- `scripts/add-loader.py` — درج خودکار لودر در همه‌ی صفحات (بی‌خطر برای اجرای دوباره)

### نکات مهم طراحی

- لودر با آماده‌شدن ساختار صفحه (`DOMContentLoaded`) کنار می‌رود، **نه** با اتمام دانلود عکس‌ها؛
  پس اگر اینترنت کاربر کند باشد، صفحه معطل نمی‌ماند.
- اگر خطایی در صفحه رخ دهد، لودر حداکثر تا ۵ ثانیه بعد بسته می‌شود (قفل اطمینان).
- لودر بعد از محو‌شدن **از DOM حذف می‌شود** تا در عکس‌های گوگل یا اسکرین‌شات‌ها نماند.

## ۲) ویرایش متن‌ها و عکس‌ها از پنل ادمین

### ایده‌ی کار

هر متن یا عکسی که قابل ویرایش است، در HTML یک «کلید» گرفته است:

```html
<h2 data-content="home.courses_title">جدیدترین دوره‌ها، جزوه‌ها و کتاب‌ها</h2>
```

فهرست همه‌ی کلیدها در `js/content-manifest.js` است. اگر مقدار کلیدی در دیتابیس
ذخیره شده باشد، `js/site-content.js` آن را جای متن پیش‌فرض می‌گذارد. اگر نباشد،
همان متن HTML نمایش داده می‌شود.

**نتیجه‌ی مهم:** سایت هرگز خالی یا خراب نشان داده نمی‌شود؛ حتی اگر دیتابیس یا
فانکشن از کار بیفتد، متن‌های اصلی سر جای خودشان هستند (برای سئو هم بی‌خطر است).

### چه چیزهایی الان قابل ویرایش است؟ (۷۸ مورد)

| گروه | نمونه‌ها |
|---|---|
| صفحه اصلی — هدر | بج بالای عنوان، عنوان دو خطی، توضیح، دو دکمه، عکس استاد، سه عدد آمار + برچسب‌ها |
| صفحه اصلی — دوره‌ها | برچسب، عنوان، توضیح، متن لینک «مشاهده همه» |
| صفحه اصلی — معرفی استاد | عنوان + دو پاراگراف (متن مهم سئو) |
| صفحه اصلی — چهار ویژگی | عنوان و توضیح بخش + عنوان و توضیح هر ۴ ویژگی |
| صفحه اصلی — مسیر شروع | عنوان بخش + عنوان و توضیح هر ۳ قدم |
| صفحه اصلی — پرسش‌های متداول | برچسب و عنوان، ۵ پرسش و ۵ پاسخ، متن و دکمه‌ی کارت پشتیبانی |
| درباره ما | عنوان، پاراگراف‌های معرفی، عکس، عنوان و پاراگراف‌های رزومه، چهار کارت آمار، بخش شبکه‌های اجتماعی و آمارها |
| صفحه دوره‌ها | عنوان و توضیح بالای صفحه |
| مشترک (فوتر) | نام برند، متن کپی‌رایت، متن نمونه‌های رایگان |

### نحوه‌ی استفاده

1. وارد پنل شوید: `/admin-login` → سپس `/admin`
2. تب **محتوای سایت** را بزنید
3. متن‌ها را ویرایش کنید (کادرهای زرد = ذخیره‌نشده)
4. برای عکس: **انتخاب و آپلود عکس** → عکس خودکار فشرده می‌شود و آپلود می‌شود
5. دکمه‌ی بنفش پایین صفحه: **ذخیره N تغییر**
6. سایت را باز کنید و با `Ctrl+F5` تازه کنید

### بازگشت به حالت اولیه

هر فیلد دکمه‌ی **بازگشت** دارد؛ همچنین هر بخش دکمه‌ی «بازگردانی همه‌ی این بخش».
بازگردانی یعنی «همان متن پیش‌فرضی که برنامه‌نویس نوشته بود».

### دو نکته‌ی حرفه‌ای

- **متن خالی = پیش‌فرض.** برای برگشتن به متن اصلی لازم نیست چیزی بنویسید؛ فقط
  «بازگشت» را بزنید.
- **کلیدواژه‌ها را نگه دارید.** متن‌های بخش «معرفی استاد» همان چیزی است که گوگل
  می‌خواند؛ اگر پاکشان کنید رتبه‌تان ضعیف می‌شود.

### افزودن یک متن جدید به لیست ویرایش (برای آینده)

1. در HTML، به متن موردنظر attribute بدهید: `data-content="کلید.یکتا"`
2. در `js/content-manifest.js` یک آیتم در گروه مناسب اضافه کنید (کلید، برچسب، پیش‌فرض)
3. `python3 scripts/add-content-keys.py` (اگر می‌خواهید با اسکریپت انجام شود)
4. `cd tests && node run-all.mjs` — تست‌ها هم‌خوانی HTML و فهرست را چک می‌کنند

## ۳) لوگوهای شبکه‌های اجتماعی در صفحه درباره ما

- چهار کارت با **لوگوی رسمی هر پلتفرم** (تلگرام آبی، بله سبز، آپارات سرخ، اینستاگرام گرادیان)
- هر کارت: نوار رنگی بالای کارت، لوگو، نام پلتفرم، آدرس (`dir="ltr"`)، آمار عضو
- همه‌ی لوگوها SVG درون‌خطی هستند: بدون درخواست شبکه، بدون فایل جانبی، با کیفیت در هر اندازه
- لینک‌ها `rel="me"` دارند تا گوگل این صفحه‌ها را به سایت رسمی نسبت دهد

## ۴) راه‌اندازی در نسخه‌ی self-hosted

> متن‌های پیش‌فرض HTML همچنان در صورت نبود محتوای ذخیره‌شده نمایش داده می‌شوند. برای ذخیره/بازگردانی از پنل، PostgreSQL، مدیر اولیه و volume محلی Storage باید آماده باشند. کد فعال Next.js دیگر به Supabase متصل نیست.

### گام ۱ — اجرای schema روی PostgreSQL مستقل

در Compose، سرویس `migrate` فایل‌های `apps/next-app/db/migrations/` را اجرا می‌کند؛ migration مقصد را روی Supabase اجرا نکنید. DDL از inventory بازسازی شده و هنوز PostgreSQL واقعی validate نشده است؛ اجرای نخست را روی staging disposable انجام دهید.

### گام ۲ — ساخت مدیر و اجرای سرویس‌ها

از راهنمای [`deploy/self-hosted/README.md`](../deploy/self-hosted/README.md) برای ساخت `.env`، راه‌اندازی Compose و اجرای bootstrap تعاملی `scripts/create-admin.js` پیروی کنید. Runtime برای content و Storage به Supabase secret نیاز ندارد.

`GET /api/site-content` محتوای عمومی را از `public.site_content` در PostgreSQL می‌خواند. ذخیره/بازگردانی در `POST /api/functions/site-content` با نشست PostgreSQL و نقش `admin` انجام می‌شود. آپلود تصویر از `admin-upload-url` توکن محلی HMAC می‌گیرد و فایل در volume محلی می‌رود؛ عکس از Nginx public سرو می‌شود.

### گام ۳ — آزمایش

در staging پس از ساخت مدیر و یک دوره، در پنل → تب **محتوای سایت** متنی را عوض و ذخیره کنید، صفحه را تازه کنید، سپس reset/restore را هم امتحان کنید. پیش از production باید این flow روی PostgreSQL واقعی و volume Docker آزموده شود.

## ۵) تست‌ها

```bash
cd apps/next-app && npm test
cd ../../tests && npm test
```

تست‌های Next با mock و تست‌های rootِ رابط سایت را جدا اجرا کنید:

- `apps/next-app/test/admin-read.test.js`: خواندن عمومی و ذخیره/بازگردانی از PostgreSQL، کنترل نقش مدیر، پاک‌سازی ورودی و attribution مدیر.
- `tests/content.test.mjs`: وجود لودر در ۱۴ صفحه، رفتار آن در jsdom، هم‌خوانی کلیدهای `content-manifest.js` با `data-content`، اعمال متن/عدد/عکس در HTML و اتصال تب محتوا به پنل.
- تست legacy `site-content` در مجموعه‌ی root صرفاً برای regression کد قدیمی Edge است؛ آن فانکشن مسیر فعال سایت نیست.
